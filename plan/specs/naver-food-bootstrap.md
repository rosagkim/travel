# 네이버 음식점 쿠폰 조사와 초기 데이터 세팅

상태: 완료

## 논의 배경

사용자가 “네이버에서 음식점 위주로 쿠폰을 뒤져봐. 그 결과로 초기 세팅을 해”라고 요청했다. 웹에서 실제 확인한 쿠폰을 초기 데이터의 근거로 삼는다.

## 목표와 범위

### 목표

네이버 음식점 쿠폰을 조사하고 출처·지역·업종·혜택·조건·검증 상태를 관리할 초기 데이터와 운영 설정을 만든다.

### 포함할 내용

- 네이버 공개 검색과 공식 음식점 기획전, 공식 쿠폰 이용 도움말 조사.
- 공개 응답에서 확보한 쿠폰을 중복 제거해 후보 데이터로 저장.
- 조사 결과를 근거로 초기 수집 지역과 업종, 검수·갱신 정책 설정.
- 필수 데이터 검사와 공개 가능 여부 판단 로직 및 검증.

### 제외할 내용

- 사용자 대신 로그인, 쿠폰 다운로드·발급·사용, 예약, 결제.
- 접근 제한 우회, 상시 자동 크롤링 가동.
- 이번 세팅에서 서비스 화면 구현. 데이터 기반을 먼저 준비한다.

## 사용자 흐름

운영자가 공개 출처에서 후보를 수집 → 혜택·유효기간·사용 조건·매장·외국인 사용 요건 검수 → 데이터 검사 → 검수와 최신성 기준을 충족한 쿠폰만 추후 지역·업종 탐색에 노출 → 원본 서비스에서 발급·사용.

## 완료 조건

- [x] 조사 출처와 접근 한계, 실제 쿠폰 사례를 기록한다.
- [x] 출처·원본 식별자·위치·업종을 포함한 중복 없는 초기 후보 데이터를 저장한다.
- [x] 미확인 유효기간·조건·외국인 사용 가능성을 추정값으로 채우지 않는다.
- [x] 초기 수집 지역·업종·검수·갱신 설정을 저장하고 자동 수집은 비활성화한다.
- [x] 미검수·기한 만료·검수 시점 경과 쿠폰의 공개를 막는 검사와 테스트가 통과한다.
- [x] 프로젝트 검사·빌드를 통과하고 main 푸시 후 배포 결과를 확인한다.

## 열린 질문

- 개별 쿠폰 상세 검수를 위한 접근 방법과 데이터 재사용·지속 수집 조건 확인.
- 첫 사용자 화면의 언어와 제공 형태, 상세 디자인.
- 수집 범위 확장 및 운영 인력·갱신 주기 조정.
