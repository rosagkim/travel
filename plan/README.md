# 기획 시작 문서

새 대화나 개발 작업을 시작할 때 이 문서와 [합의 기록](decisions.md)을 먼저 읽습니다. 서비스 방향은 방한 외국인 관광객 대상 쿠폰 앱이며, 상세 기획은 논의 중입니다.

## 현재 맥락

- 서비스 방향: 한국을 방문하는 외국인 관광객에게 한국에서 사용할 수 있는 쿠폰을 모아 제공하는 앱.
- 실제 제품 기획: [방한 외국인 관광객 쿠폰 앱](specs/tourist-coupons.md) 초안. 웹 쿠폰 전반의 수집과 핵심 탐색·안내 흐름을 확인했으며, 초기 수집 범위와 운영·구현 방식은 논의 중입니다.
- 초기 데이터: [네이버 음식점 조사와 세팅](specs/naver-food-bootstrap.md). 공개 출처에서 17개 매장·23개 쿠폰 후보를 확보했고, 개별 사용 조건은 검수 전입니다. 근거는 [조사 기록](research/naver-food-2026-10-29.md)에 있습니다.
- 사이트: [쿠폰 탐색 화면과 자동 배포](specs/coupon-explorer.md). 영어·한국어로 쿠폰 후보를 탐색하고 지역·업종·검색어로 필터링하며 상세와 원본·위치 링크를 제공합니다. 미확인 조건은 명시합니다.
- 다음 행동: 원본 쿠폰의 유효기간·상세 조건·외국인 사용 요건을 검수하고, 첫 사용자 화면의 언어와 제공 형태를 구체화합니다. 자동 수집은 비활성화 상태입니다.

진행 상황이 바뀌면 이 부분에 현재 작업, 남은 질문, 다음 행동을 짧게 갱신합니다. 상세 요구사항은 해당 기획 파일에 한 번만 기록합니다.

## 논의에서 개발까지

1. 아이디어와 미정인 내용은 주제별 초안에 기록합니다. 비어 있는 주제 파일을 미리 만들지 않습니다.
2. 대화에서 합의가 확인되면 범위와 완료 조건을 구체화하고 상태를 `합의`로 바꿉니다. 이미 확인한 합의에 대해 승인을 반복해서 요청하지 않습니다.
3. 구현을 시작하면 `구현 중`으로 바꾸고 관련 코드 위치를 연결합니다.
4. 완료 조건을 실제로 확인한 뒤 체크하고 검증 결과를 기록해 `완료`로 바꿉니다.
5. 방향이 바뀌면 기존 문서와 결정의 변경 이유를 남깁니다. 중단한 기획은 이유와 함께 `보류`로 유지합니다.

상태는 `초안 → 합의 → 구현 중 → 완료`를 사용하며, 중단 시 `보류`로 바꿉니다. 상태는 파일에서 직접 수정합니다. 도구가 합의를 대신 판단하지 않습니다.

## 명령

```sh
npm run plan:new -- feature-name "논의 주제"
npm run plan:list
npm run plan:check
```

생성 명령은 `specs/feature-name.md`를 초안 상태로 만들며 기존 파일을 덮어쓰지 않습니다. 목록은 파일에서 직접 읽으므로 별도 목록이나 상태 파일을 맞출 필요가 없습니다.

검사에서는 상태, 필수 항목, 로컬 파일 링크를 확인합니다. `합의` 이후에는 핵심 범위에 미정인 항목을 남길 수 없으며 완료 조건 체크리스트가 필요합니다. `완료` 상태에서는 모든 완료 조건과 구현·검증 기록이 필요합니다. 검사는 대화에서 실제로 합의했는지나 기능이 올바르게 동작하는지까지 판단하지 않습니다.

Git 커밋으로 문서와 코드의 변경 이력을 함께 남깁니다. 필요하면 `git log -- plan/` 또는 `git log -p -- plan/specs/<주제>.md`로 이전 내용을 확인합니다.
