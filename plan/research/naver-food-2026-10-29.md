## 조사 방법과 결과

한국 시간 2026-10-29에 네이버 공개 검색 6개 질의와 원본 페이지를 확인했다. 사용자 계정 로그인, 쿠폰 발급·다운로드·사용, 예약·결제는 하지 않았다. 검색 상위 결과의 편의 표본이며 전국 쿠폰 분포나 지역별 수요를 대표하지 않는다.

검색에서 발견한 [네이버 공식 Seoul Food Map: Hongdae·Mapo](https://booking.map.naver.com/promotions/pioa3d2oskuc)의 공개 HTML과 그 응답에 포함된 구조화 데이터를 확인했다. 해당 응답에서 중복 제거한 매장 20개 중 17개 매장에 쿠폰 23건이 있었다. 화면에 처음 표시된 10개 매장 외에 응답에 포함된 추가 매장도 있으므로, 23건 전체를 화면에서 직접 열어 확인했다고 해석하면 안 된다. 기획전의 `346 total` 표시는 쿠폰 수가 아니며 이번 수집 건수에도 포함하지 않는다.

목록에서 확인한 쿠폰 제목·식별자·출처 링크·좌표·지역 필터·업종만 사실로 저장했다. 쿠폰 상세 사용 가능성은 별도 검수 전이다. 원본의 영문 매장명과 한국어 쿠폰 제목을 유지하며, 검증하지 않은 한국어 매장명이나 번역은 만들지 않았다. 음식점 기획전에 포함된 주점·이자카야도 업종으로 구분해 저장했다.

## 실제 확인한 사용 흐름과 접근 한계

- [네이버 공식 쿠폰 이용 도움말](https://help.naver.com/service/11713/contents/20805)의 공개 HTML 메타 설명에서 매장 방문/N예약/N주문별 사용, 매장 직원 코드 입력 및 스마트폰 화면 확인 가능성, 유효기간·요일·시간 조건, 중복 사용 제한, MY플레이스 쿠폰 확인 방법을 확인했다. 이는 일반 안내이며 개별 쿠폰 조건의 증거로 대체하지 않는다.
- 와라라 쿠폰 목록 원본은 공개 응답에서 네이버 로그인 안내를 표시했다. 영어 개별 쿠폰 상세 두 곳은 `loading` 껍데기만 반환했다. 따라서 상세 유효기간이나 사용 요건을 확인한 것으로 처리하지 않았다.
- 양산도·연남달빛의 플레이스 상세 공개 요청은 HTTP 429를 반환했다. 이후 해당 상세 수집을 중단했다. 접근 제한을 우회하거나 추가 반복 요청하지 않았다.
- 모든 초기 후보의 유효기간·정확한 사용 조건·전화번호/본인인증/결제 요건은 미확인이다. `ALL`이나 `PLACE_HOME` 원문 값을 ‘무조건 사용 가능’으로 해석하지 않는다. 증정 쿠폰 제목에 금액이 들어가도 현금 할인액으로 파싱하지 않는다.
- 원본 목록 공개는 데이터의 재사용 허용이나 지속 크롤링 허가를 의미하지 않는다. 자동 수집 전 수집처 이용 조건과 접근 방식 확인이 필요하다.

## 이번 초기 세팅

- 초기 수집 범위는 서울 마포구 홍대·연남·합정·망원·공덕·신촌의 음식점과 기획전 포함 주점으로 설정한다. 비교 지역보다 쿠폰이 많다는 결론이 아니라, 위치와 원본 링크를 함께 확보한 출처부터 시작하는 구현 선택이다.
- 기획전의 `connect` 필터는 동네 이름이 아니므로 세부 지역을 비워 두고 구 단위에서만 다룬다. 주소 원문은 `Seoul`뿐이어서 상세 주소는 미확인으로 남긴다.
- 발견과 검수를 분리한다. 현재 23건은 전부 `needs-review`이고 공개 가능한 쿠폰은 0건이다. 만료일을 임의로 넣거나 ‘상시’로 표시하지 않는다.
- 원본 서비스에서 쿠폰 발급·사용하도록 연결한다. 우리 앱에서 쿠폰을 재발급하거나 캡처 화면으로 사용 가능하다고 안내하지 않는다.
- 향후 검수 목표는 24시간이다. 자동 수집과 정기 실행은 비활성화 상태이며 실제 스케줄을 등록하지 않았다. 이 주기는 수집처 접근 조건과 운영량을 확인한 후 조정한다.
- 일반 쿠폰 목록과 네이버 적립 행사 배지는 구분한다. 예를 들어 `20% Points`는 할인 쿠폰 혜택으로 저장하지 않았다. 메뉴 가격 `0`도 무료 쿠폰으로 해석하지 않았다.
