# 합의 기록

사용자와 확인한 결정만 기록합니다. 제안이나 추측은 기획의 열린 질문에 둡니다. 결정을 바꿀 때는 기존 기록을 지우지 않고 새 결정에서 대체한 결정 ID와 이유를 남깁니다.

## D-001 · 서비스는 함께 기획한 뒤 구현

- 결정: 서비스의 목적과 기능은 아직 미정입니다. 합의 전까지 사이트는 빈 화면으로 유지합니다.
- 근거: 사용자 요청 — “아직 무슨 사이트를 만들지는 안 정했고 같이 기획해서 개발을 잘 할 수 있게 하자는 거야.”
- 이유: 확정하지 않은 서비스나 기획용 사이트를 임의로 만들지 않기 위해서입니다.

## D-002 · main에서 직접 자동 배포

- 결정: main 푸시 시 GitHub Actions가 검증·빌드하고 Pages에 직접 배포합니다.
- 근거: 사용자 요청 — “별도의 브랜치 없이 메인 브랜치를 기반으로 알아서 빌드되서 배포되게 해줘.”
- 결과: 별도 배포 브랜치를 사용하지 않습니다.

## D-003 · 기획은 저장소의 마크다운으로 관리

- 결정: 논의한 기획을 plan/에 저장하고, 합의·미정·진행 상황과 변경 이유를 구분합니다. 사이트에 기획 관리 화면을 만들지 않습니다.
- 근거: 사용자 요청 — “기획된 내용을 plan 폴더에 마크다운으로 정리”, “기획한 내용을 잘 저장 관리할 수 있는 시스템에 집중해서 개선해.”
- 결과: 현재 맥락은 시작 문서, 결정은 이 문서, 상세 기획은 주제별 파일에서 관리합니다. 실제 제품 기획은 아직 없습니다.
